# Statistical objects

## Purpose

This note fixes the objects used throughout the package. The main design rule is to avoid mixing empirical data, deterministic audit paths, and hypothetical stochastic simulations.

## Evidence objects

### Empirical benchmark data: `D_emp`

`D_emp` refers to observed grouped datasets used in the three empirical benchmarks:

- optical spectra;
- RTD curves;
- drying curves.

These datasets support empirical evidence ledgers and grouped holdout risks. Dense point sampling does not imply a large number of independent deployment groups.

### Deterministic residual-anchored path: `D_path(alpha)`

`D_path(alpha)` is used only in the controlled conflict-resolution audit. It is generated by modifying the observed drying design along a deterministic Page-to-Midilli intervention path while retaining the same residual pattern. It is not a new empirical dataset, not a bootstrap, not a Monte Carlo simulation, and not an independent validation benchmark.

The path exists to audit the behavior of the declared decision rule, not to establish repeated-sampling operating characteristics.

### Stochastic simulation object: `D_sim`

`D_sim` would require a fully specified data-generating process, noise distribution, group-level heterogeneity structure, replicate count, and Monte Carlo uncertainty reporting. This package does not report `D_sim` evidence.

## Candidate library

`M_set` denotes the finite candidate library. Each model `M` has:

- a fitted response function;
- a parameter count `k_M`;
- a training SSE;
- a grouped-CV risk;
- a BIC-style structural signal;
- a baseline-relative predictive gain;
- a RIEC-L1 score.

The library is finite and reviewable; RIEC-L1 is not defined as a search over an unrestricted hypothesis space.

## Group labels

`G` denotes deployment-relevant groups. Group labels are case-specific:

- optics: material-angle conditions;
- RTD: runs;
- drying: operating conditions.

Grouped holdout is used to evaluate deployment-aligned risk.

## Evidence ledger

The evidence ledger `L(D, M_set)` is descriptive. It stores the computed quantities for each candidate. A ledger by itself is not a decision rule. It can show that BIC and grouped CV disagree, but it does not specify what to do with the disagreement.

## Decision context

The decision context `theta` contains the declared choices required before selecting a model:

- candidate library;
- baseline `M0`;
- grouping structure;
- `n_eff` penalty-calibration input;
- schedule parameter `c`;
- score formula and tie-handling convention.

## Choice map

`delta_theta` maps the ledger to a recommendation. For RIEC-L1:

```text
delta_theta^RIEC[L(D, M_set)] = argmin_M C_lambda(M)
```

The recommendation is conditional on `theta`; it is not a universal statement that the chosen candidate is truly best in all senses.

## Audit quantities

The key audit quantities are:

- `G_theta(M)`: score gap from the winner;
- `G_theta*`: runner-up conflict margin;
- pairwise switching boundary;
- `c` switchpoint;
- compact-versus-flexible margin in the controlled path.

These are not p-values, posterior probabilities, or confidence intervals. They are score-scale diagnostics for the declared decision rule.
